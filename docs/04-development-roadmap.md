## 已完成的 V1 收尾增强

- 课表：自适应网格、跨节课程块、单双周、冲突课程并列轨道、双指捏合缩放、可配置节次与学期。
- 跨页面生活回顾：Calendar 与 Journal 共享每日生活摘要，习惯可在月历、日记和完成轨迹中同步。
- 数据安全：用户选择文件权限、版本化 `.lifeosbackup`、自动快照与恢复前保护点。
- 视觉：Warm Minimal Life OS 设计令牌、响应式 Calendar／Journal 布局和 Dock 应用图标。
- 工程治理：开发日志、Git 仓库、每次完成改动的聚焦提交与验证要求。

## 后续推进顺序

当前不自动进入 V2／V3。下一项工作必须从下列稳定性和产品决策中选择一个独立目标：

1. **V1 回归与可访问性**：在浅色／深色、最小窗口、空数据和人工测试数据下完成手工回归；补充可访问性标签和键盘路径检查。
2. **备份恢复演练**：以真实本机数据验证“自动保护 → 恢复 → 回退”的流程，并为未来格式升级明确迁移策略。
3. **课程例外规则评估**：如需调课／停课／补课，先设计单次例外模型与对 Today／Calendar／课表的影响，再修改 Schema。
4. **V2.1 今日节奏（需单独立项）**：先做可解释的连续占用与缓冲提示；不自动重排、不修改任何任务或日程。
5. **V2.2 课程成长档案（需单独立项）**：将课程、关联任务、作业、考试与日记足迹动态聚合在课程详情，先完成读取与回跳，再讨论进度模型。
6. **V2.3 一天生活回放与每周收束（需单独立项）**：从日历和日记的已有数据生成回顾；不引入独立统计页或重复每日／每周实体。
7. **V3 本地优先助手（需用户确认）**：仅在用户选择服务、隐私边界、数据授权和可解释输出标准后开始设计。

## 每次变更的执行顺序

1. 阅读适用的 `docs/` 标准与既有决策。
2. 在当天开发日志记录 todo。
3. 只实现一个可独立验证的目标；避免顺手重构无关模块。
4. 为新增／变更领域规则添加或更新单元测试；执行受影响的构建与测试。
5. 更新受影响的需求、架构、模型、UI 或决策文档。
6. 在开发日志记录验证和遗留事项。
7. 创建只包含本次源代码、测试、文档和日志的 Git commit，再交付结果。
